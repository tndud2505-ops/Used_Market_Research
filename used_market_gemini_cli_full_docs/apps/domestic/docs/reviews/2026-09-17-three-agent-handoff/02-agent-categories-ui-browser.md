# 에이전트 2 — 카테고리·필터·분석/견적 UI·브라우저 검증

## 역할과 경계

USED PICK의 기존 화면을 일반 사용자가 부품별로 쉽게 고르게 만드는 작업을 마무리한다.
새 앱을 만들지 않는다. 같은 폴더 `00-current-state-and-blockers.md`를 먼저 끝까지 읽는다.
운영 쓰기 담당은 에이전트 1이다. DB 변경·수집·게시·서비스 제어·Worker deploy·통합 git 작업을 하지 않는다.
외부 AI/CLI/브라우저 에이전트 실행 전 루트가 요구하는 실제 스킬과 실행 권한을 확인한다.

## 소유 파일

- `web-backend/public/pc-tools-catalog.mjs`, `pc-tools-core.mjs`, `pc-tools-data.mjs`
- `web-backend/public/pc-tools.js`, `pc-tools.css`, `computer-builder.html`, `price-analysis.html`, `index.html`
- 프런트엔드 관련 하네스와 `tmp/pc-live-v18-browser.mjs`
- 기존 공유 하네스를 다른 담당자가 수정 중이면 역할 전용 하네스로 분리하고 통합 요청한다.
- `market/**`, `aws-runner/**`, `cloudflare/**`의 API·분류 계약 변경은 직접 수정하지 말고 에이전트 1/3에게 요청한다.

## 이미 있는 기능과 이번에 남은 목표

세부 필터 개선 코드, G.Skill 검색 별칭, 빈 검색 차트 초기화, 부분 합계 안내, 모바일 CSS는 이전 수정본에 있다.
이를 새 개발 성과로 중복 보고하지 말고 현재 코드/화면을 확인해 결함을 고친다.
공개 카탈로그는 14:02 조회 당시 v4였다. 로컬 수정본의 존재와 운영 화면 반영을 구분한다.

기존 승인 범위는 메인 매물 검색 7개, 컴퓨터 맞추기/가격 분석 9개, 내부 수집 11개다.
케이스·쿨러를 메인 검색에 새로 추가하는 7→9 확대는 이번에 자동으로 승인됐다고 해석하지 않는다.
기존 범위 안에서 아래 카테고리별 선택을 이해하기 쉽고 실제로 연결되게 만든다.

| 부품 | 선택 기준 |
|---|---|
| CPU | 제조사·세대·소켓·제품 |
| GPU | 칩 제조사·세대·VRAM·제품; 보드 제조사와 구분 |
| RAM | 모듈 제조사·DDR 세대·개당 용량·수량 |
| 메인보드 | 실제 보드 제조사·소켓·칩셋·검증된 정확 모델 |
| SSD/HDD | 제조사·용량 구간; 정확 모델 가격으로 오인하지 않는 안내 |
| 파워 | 제조사·정격 출력; 폼팩터/효율/케이블 확인 안내 |
| 케이스 | 제조사·크기/종류 참고 시세 |
| 쿨러 | 제조사·공랭/수랭/팬 종류 참고 시세 |

탐색 전용 메인보드 10개는 가격 선택에서 제외하고, 788개 가격 항목과 별도 검증한다.
RAM은 16GB 두 개로 32GB를 구성할 때 16GB 단가×2가 보이게 한다.
고급 규격이 카탈로그에 없으면 임의로 선택 옵션이나 호환성을 만들어 내지 않는다.

## 구체 작업

1. 현재 UI에서 조건 전환·선택된 제품·URL·분석 차트·견적 항목이 같은 canonical ID를 가리키는지 확인한다.
   제조사 전환 후 이전 제품 가격이 남거나, 빈 검색인데 이전 차트가 남는 문제를 재현하고 수정한다.
   선택 불가능한 조합, 0건 안내, 조건 초기화가 이해 가능한지 확인한다.

2. 분석 화면의 기존 브라우저 진단은 숨겨진 선택기 대기 및 이후 검색 입력 대기 실패가 있었다.
   응답 HTML·스크립트 오류·DOM·선택기 조건을 실제로 조사해 테스트 오류와 제품 오류를 구분한다.
   타임아웃만 늘리거나 검사를 삭제해 통과하지 않는다.

3. 모바일은 실제 390×844와 데스크톱에서 모델명/가격/수량/조작 버튼/차트 축을 눈으로 확인한다.
   이전 운영 스크린샷에는 잘림이 있었다. document.scrollWidth 검사 하나로 가독성 PASS를 주지 않는다.
   긴 제품명·큰 금액·빈 결과·9종 견적에서도 잘리지 않게 수정한다.

4. 저장·새로고침·수량 변경·잘못된 수량 복구·삭제가 실제로 동작하는지 확인한다.
   매물 이동 링크가 정확한 모델 선택으로 이어지는지 확인한다.
   사이트 선택 시 KRW/USD와 시장 조건이 맞는지 확인하고 환율 없는 통화를 합산하지 않는다.
   확인 가능한 CPU 소켓/DDR 충돌은 경고하고, 정보 없는 호환성을 보장하지 않는다.

5. 에이전트 3과 API/표본/가격 단위 계약을 맞춘다.
   n<3은 가격 없음, 3~4는 중앙값. 자료 부족은 부분 합계로 표시한다.
   API 내부 오류나 게시 준비 미완료를 실제 시장 표본 부족으로 오인시키지 않는다.
   유효한 소스를 전부 숨겨 오류를 없애거나 임의 가격을 채우지 않는다.

6. 로컬 테스트는 먼저 수행해도 된다. 모의 데이터는 '로컬 합성 테스트'라고 분명히 기록한다.
   배포 이후에는 에이전트 1이 고정한 공개 릴리스를 대상으로 실제 API·실제 브라우저를 검증한다.
   원 사이트 실수집을 유발하는 API나 관리자 경로를 호출하지 않는다.
   일반 사용자 URL의 캐시를 확인한다. 캐시 우회 쿼리만으로 완료 처리하지 않는다.

7. 브라우저는 하나 또는 둘의 격리된 context/profile만 재사용한다.
   사용자 개인 브라우저/로그인 프로필/저장 견적은 건드리지 않는다. 본인 테스트 context의 견적만 저장·삭제한다.
   종료 시 본인이 만든 브라우저를 닫고 evidence를 남긴다.

## 9종 견적 검사

기존 `tmp/pc-live-v18-browser.mjs`를 실행·수정해 9개 부품군 + RAM 수량 2, 총 수량 10을 확인한다.
기대 합계는 앱 buildTotals/coherentStats 등 집계 함수를 재사용하지 않고 원 API로 독립 계산한다.
각 행에 ID/사이트·시장/통화/기간/게시 ID/단가/수량/행 합계를 남긴다.
소켓과 DDR을 의도적으로 충돌시키는 조합은 '비호환 경고 테스트'라고 기록하고 추천 견적이라고 하지 않는다.
분석 요약·견적 합계·부분 가격 포함 수·실제 화면 텍스트가 일치하는지 확인한다.
게시가 아직 실패 상태라면 그 의존 항목만 미실행/BLOCKED로 남기고 나머지 로컬 UI 수정을 진행한다.
