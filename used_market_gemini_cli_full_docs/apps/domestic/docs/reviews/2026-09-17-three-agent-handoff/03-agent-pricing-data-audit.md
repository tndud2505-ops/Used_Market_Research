# 에이전트 3 — 분류·정확 통계·실수집 증거·독립 API 감사

## 역할과 경계

USED PICK의 검색 → 분류 → 통계 → 분석 → 견적이 같은 제품·가격 단위로 연결되는지 검증하고 결함을 수정한다.
먼저 같은 폴더의 `00-current-state-and-blockers.md`와 기존 상세 인수인계서를 읽는다.
운영 DB/정규화/원본 수집/게시/서비스/Worker 쓰기 담당은 에이전트 1뿐이다.
운영 자료는 읽기 전용 조회 또는 일관된 검증 사본으로 다룬다. PcPartsLedger.migrate/초기화가 포함된
쓰기 가능한 검증 스크립트를 운영 DB에 '읽기 검사'라고 실행하지 않는다.

## 소유 파일

- 게시 전송 코드·Worker·서비스 제어 변경은 에이전트 1에 요청한다. 프런트엔드 변경은 에이전트 2에 요청한다.
- 공유 하네스는 동시 수정하지 않는다. 패치·테스트 추가 요구를 통합 담당에게 전달한다.

## 현재 가장 중요한 결함

운영 v18은 이미 활성이다. 두 차례 통계 import 503 후 로컬 완료 게시 수는 0이다.
14:02 공개 G.Skill DDR4 16GB active=37/sold=8, DDR5 16GB active=44/sold=5였지만
평균/중앙값과 게시 ID가 없고 aggregate_incomplete=true, 구성원 수 null이었다.
이 값은 완성된 고유 매물 기간 요약이 아니다. 내부 게시 문제를 시장 표본 부족으로 덮지 않는다.
에이전트 1의 503 복구와 별개로 통계 대상·구성원·집계 단위의 정확성을 확인한다.

## 실행 과업

1. 운영 최신 버전과 소스 해시를 기록한다. 이미 검증된 사본/실제 적용 보고서/실수집 결과를 재사용한다.
   현재 v18의 분류 의미를 바꾸면 v18 결과를 몰래 덮어쓰지 말고 후속 버전과 영향 범위를 제안한다.
   새 버전이 운영에 있으면 v18로 되돌리지 않는다.

2. 지스킬 27개 등록 항목별로 다음을 표로 만든다.
   - 동일 ID 집합으로 검색되는 다섯 표기: G.Skill/gskill/G SKILL/G-SKILL/지스킬
   - 국내 한글 대상의 실제 요청·수신·저장·요청 제품 일치·제외 사유
   - 유효 고유 매물 수, 판매중/판매완료 표본 수, 가격 정책, 대표값 유무
   - 가격 없음 원인: 실제 표본 없음/1~2건/조건 제외/미등록/내부 통계 또는 게시 오류
   검색 성공 27개를 27개 모두 가격 확보로 바꾸어 보고하지 않는다.

3. RAM은 총용량·모듈 용량·수량·표시가격 범위를 분리한다.
   `32GB(16GB×2)` → 16GB 2개, 총액 290,000이면 단가 145,000이라는 실제 저장 예제가 있다.
   총용량이 일치하는 표기, KIT 없음, 2×16GB/16기가×2, each/per module/개당,
   모순 용량·수량만 명시·일부 판매·고장·방열판·노트북/서버용·칩 제조사 혼동을 재검사한다.
   정상 키트를 복원하되 애매한 가격을 임의로 반으로 나누지 않는다.

4. 9개 부품군 각각의 검색·분류 ID·가격 단위·조건·시장·통화·기간을 대조한다.
   CPU/GPU/RAM/메인보드/SSD/HDD/파워/케이스/쿨러를 빠짐없이 확인한다.
   메인보드 탐색 전용 10개는 가격 항목이 아니다. 넓은 참고 시세를 정확 모델 가격으로 만들지 않는다.
   현재 가격 선택 788개 검사는 합성 등록 범위 검사이며 모든 시장 부품 검사가 아니다.

5. 실제 미분류/미등록 관측을 재검사한다. 기존 80개 표본에는 Intel 랜카드의 CPU/메인보드 오분류,
   WD SN520 NVME SSD 128G, 일부 리안리·다크플래시 케이스 표현 등이 후보로 남아 있다.
   단순 검색 잡음/부적합 매물과 누락된 정상 부품을 구분한다. 80개가 모든 미분류를 대표한다고 주장하지 않는다.
   새 정확 모델을 등록할 때는 제조사 공식 자료로 규격·변형을 확인하고 부정 사례 테스트를 추가한다.
   불확실한 제품을 억지로 등록하거나 기존 다른 ID의 가격을 가져오지 않는다.

6. 전체 게시의 범위 완전성을 에이전트 1에게 검증 자료로 제공한다.
   과거 D1 2,294행과 실패한 준비 2,086행의 실제 키 차집합을 현재 D1 조회와 비교한다.
   로컬 완료 게시 0개인 상태에서 로컬 직전 게시만 조회하는 fullPublicationScopes의 첫 전환 전제를 확인한다.
   필요한 기존 범위는 새 버전·같은 시각으로 계산한다. 이전 가격 값 재사용 금지.
   게시 ID/checksum/행 수/키 집합/구성원 수/구성원 checksum/정규화·parser·rule·filter를 대조한다.
   같은 매물의 여러 날 관측을 다른 매물로 세거나 일별 중앙값 평균을 전체 중앙값으로 쓰지 않는다.
   공개 GET은 저장된 정확한 통계를 읽으며, 과거 as_of와 다른 최신 요약을 대신 반환하지 않는다.

7. 실제 수집 증거와 전체 대상 실행 현황을 분리한다.
   이미 국내 두 소스의 44개씩 실행은 성공 보고서가 있다. 총 2,441개 target의 전체 완료는 아니다.
   실제 pc_source_target_runtime 및 crawl_runs에서 성공/실패/시도 중/시도 없음/성공 이력 없음 상태를 구분한다.
   설정 ACTIVE나 health coverage_ready만으로 수집 완료를 판정하지 않는다.
   필요한 추가 수집과 예상 영향은 에이전트 1에게 요청한다. 직접 원 사이트에 우회 요청하지 않는다.

8. 수정 후 해당 하네스와 전체 가격 정책 테스트를 실행하고, 배포 후에는 다음을 실제 데이터로 실행한다.

```text
node tmp/pc-resume-full-audit.mjs --after
```

전수 감사는 응답 성공뿐 아니라 내부 누락·과거 기간·표본 정책·통화 분리·일반 URL 캐시를 확인한다.
현재 이후 버전으로 합의했다면 명시적 릴리스 manifest를 검사한다. 하드코딩 때문에 v18로 강제 다운그레이드하지 않는다.
에이전트 2에 독립 API 단가 표와 계약을 전달하되 화면 합계의 기대값을 앱 합산 함수로 만들지 않는다.
