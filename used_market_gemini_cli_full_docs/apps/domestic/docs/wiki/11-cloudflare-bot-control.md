# Cloudflare 봇 통제

마지막 갱신: 2026-11-12
상태: 운영자가 Cloudflare에서 봇 통제를 설정했다고 알렸다. 세부 설정값은 아직 이 저장소에 기록되지 않았다.

## 확인된 사실

- 2026-11-12 운영자가 Cloudflare(`used-pick.com` 영역)에 봇 통제를 적용했다고 직접 알렸다.
- 저장소의 기존 문서에는 이 설정의 기능 종류, 규칙, 적용 호스트·경로, 적용 시각이 없다.
- 같은 날 Chrome으로 Cloudflare 대시보드의 보안 > 봇 화면을 열어 읽으려 했으나 로그인 세션이 없어 설정을 확인하지 못했다. 로그인 정보를 입력하거나 다른 계정·토큰으로 우회하지 않았다. 어떤 기능을 켰는지는 추정해서 적지 않는다.

## 기록 칸 (운영자가 대시보드 값을 확인해 채운다)

| 항목 | 값 |
| --- | --- |
| 적용 시각(KST) | 미확인 |
| 대상 호스트 | 미확인 (`used-pick.com`, `www.used-pick.com`, `runner.used-pick.com` 중 어디인지) |
| 사용한 기능 | 미확인 (Bot Fight Mode, Super Bot Fight Mode, 봇 관리, AI 크롤러 차단, WAF 사용자 지정 규칙, 속도 제한 등) |
| 동작 | 미확인 (허용, 차단, Managed Challenge, 로그만) |
| 예외(skip) 규칙 | 미확인 |
| 변경 전 설정과 되돌리는 방법 | 미확인 |
| 규칙 ID·expression | 미확인 |

값을 채울 때는 설정을 바꾼 시각, 바꾸기 전 상태, 되돌리는 방법을 함께 적는다.

## 운영 규칙

- Worker가 AWS 러너로 보내는 요청, AWS 서버가 `runner.used-pick.com/health`를 확인하는 요청, Cloudflare cron 호출은 정상 운영 경로다. 봇 통제가 이 경로를 막으면 전체 WAF·Access·속도 제한을 해제하지 않고 해당 호스트·경로에만 좁은 예외를 둔다. 다른 User-Agent·IP·계정·토큰으로 우회하지 않는다. 2026-09-18 Browser Integrity Check 사례와 같은 원칙이다. ([기록](../reviews/2026-09-18-production-closeout/06-final-production-closeout.md))
- 예외를 만들면 규칙 ID, 정확한 expression, 전후 설정, 시각, 복구 방법을 이 문서에 남긴다. 기존 규칙을 읽고 중복 규칙을 만들지 않는다.
- 수집 대상 사이트에 대한 우리 수집기의 접근 정책은 이 설정과 별개다. 이 설정은 우리 사이트로 들어오는 요청에만 적용된다.

## 설정 뒤 확인 항목

- 공개 도메인 두 곳의 화면과 `/health`가 일반 브라우저에서 정상으로 열리는지.
- AWS 서버에서 `runner.used-pick.com/health`가 HTTP 200인지, 다음 정기 게시와 수집 회차가 막히지 않는지.
- 네이버 서치어드바이저 등록과 구글 검색을 위한 정상 검색 봇이 막히지 않는지. 네이버 등록은 2026-11-11 준비 중이다. ([기록](../daily_history/2026-11-11.md))
- 위 항목은 설정 값이 확인된 뒤 한 번 점검하고 결과를 일일 이력에 남긴다.
