# 캐시와 검색 UX

기준일: 2026-08-24

이 문서는 검색 뒤 사이트·정렬·가격·페이지를 바꿀 때 어떤 데이터를 재사용하고 언제 원 사이트를 다시 확인하는지 정한다.

## 핵심 용어

- **수집 키**: 정규화한 검색어, 카테고리, 처음 선택한 사이트 묶음이다.
- **보기 조건**: 사이트 탭, 정렬, 최소·최대 가격, 페이지다. 수집 키를 바꾸지 않는다.
- **스냅샷**: 한 수집 키로 AWS SQLite에 저장한 최대 1,000개 결과다.
- **도달 가능 페이지**: 이미 브라우저가 받은 페이지와 cursor 한 번으로 읽을 수 있는 바로 다음 페이지다.

## 데이터 경로와 캐시 층

`브라우저 → Cloudflare Worker → Named Tunnel → AWS Runner → SQLite`가 주 경로다. AWS 검색이 실패하면 Worker가 D1 저장본으로 제한된 결과를 반환한다.

| 층 | 저장 내용 | 수명·한도 | 역할 |
| --- | --- | --- | --- |
| 브라우저 메모리 | 전체 응답 `collectionData`, 사이트·정렬·가격별 `viewData` | 현재 탭의 검색 세션 | 탭 전환 때 기존 결과를 즉시 표시한다. 새로고침하면 사라진다. |
| AWS Runner 메모리 | 동일 요청 응답 | 기본 5분, 최대 64개 | 같은 서버 요청의 SQLite 처리와 직렬화를 줄인다. |
| AWS SQLite | 검색 스냅샷, cursor, 가격 이력 | 기본 fresh 6시간, 스냅샷 최대 1,000개 | 사이트·정렬·가격·페이지 조회의 기준 저장소다. stale 결과도 먼저 주고 백그라운드 갱신한다. |
| 원 사이트 메모리 | 사이트별 원본 조회 결과 | fresh 5분, stale fallback 15분, 최대 256개 | 짧은 시간의 반복 원본 요청을 줄이고 일시 실패 때 최근 원본 결과를 쓴다. |
| Cloudflare D1 | 최근 변경 매물 백업 | 전체 최대 10,000개 | AWS 5xx·연결 실패 시 제한된 첫 결과를 제공한다. AWS cursor와 동일한 확장성은 보장하지 않는다. |

## 사용자 행동별 동작

| 사용자 행동 | 즉시 보이는 것 | 서버 동작 | 원 사이트 재수집 |
| --- | --- | --- | --- |
| 새 전체 검색 | 저장 스냅샷의 첫 30개를 바로 표시 | 같은 전체 보기 cursor로 최대 90개를 선읽고, stale이면 백그라운드 갱신 | 캐시가 없거나 갱신이 필요할 때만 |
| 전체 → 중고나라 | 전체 스냅샷의 중고나라 결과 | 중고나라만 320개 후보까지 보강하고 90개를 선읽기 | 중고나라만 1회 보강 가능 |
| 중고나라 → 전체 | 보관한 전체 응답 | 같은 수집 키의 전체 보기를 조회하고 최대 90개 선읽기 | 없음 |
| 추천 ↔ 낮은 가격 ↔ 높은 가격 ↔ 최신 | 브라우저의 현재 결과를 먼저 재배열 | 같은 SQLite 스냅샷을 해당 정렬로 조회하고 전체 보기면 최대 90개 선읽기 | 없음 |
| 최소·최대 가격 적용 | 현재 결과를 유지하고 1페이지로 이동 | 같은 SQLite 스냅샷을 범위 조회하고 전체 보기면 최대 90개 선읽기 | 없음 |
| 이미 받은 페이지 이동 | 즉시 이동 | 없음 | 없음 |
| 바로 다음 도달 가능 페이지 이동 | 로딩 뒤 해당 페이지 | cursor 한 번으로 다음 30개 조회 | 없음 |
| 결과 창 끝에서 `다음` | 기존 결과 유지 | 후보 창을 160개씩 320→480→640으로 확장 | 현재 보기 사이트만 최신 후보 보강 |

정렬과 가격 필터는 수집 요청이 아니다. `낮은 가격`과 `높은 가격`은 확인한 스냅샷 안에서 숫자 가격을 1차 키로 사용하며, 원 사이트 전체에서 절대 최저가·최고가를 보장한다는 뜻은 아니다.

## 페이지 UX 계약

- 결과는 PC·모바일 모두 30개씩 표시한다.
- 새 전체 검색, 전체 보기의 정렬·가격 변경·사이트 복귀, 사이트 보강에서 최대 90개를 선읽는다.
- 90개를 받았고 다음 cursor가 있으면 1페이지에서 `1 2 3 4 … 마지막`을 표시한다.
- 1→2와 1→3은 이미 받은 90개에서 즉시 이동한다.
- 1→4는 cursor 한 번으로 다음 30개를 읽고 이동한다. 2→4, 3→4도 같은 규칙이다.
- 아직 도달할 수 없는 마지막 페이지 숫자는 총량 안내용이며 클릭할 수 없다. 1→34처럼 중간 cursor를 연속 요청하지 않는다.
- 도달 범위가 7페이지를 넘으면 `처음 · 현재 주변 · 도달 경계 · 마지막`만 보여 모바일 가로 넘침을 막는다.
- 수집 또는 페이지 요청 중에는 중복 요청을 막고, 완료되면 현재 도달 범위로 버튼을 다시 계산한다.
- 별도 `다음 매물 더 찾기` 버튼은 쓰지 않는다. 번호 페이지의 `다음`이 다음 cursor 조회 또는 결과 창 확장을 담당한다.
- 결과 요약 옆과 목록 아래의 `이전`·`다음`은 같은 페이지 상태와 클릭 계약을 공유한다.

## 실패와 최신성

- fresh SQLite 스냅샷은 즉시 사용한다.
- 6시간이 지난 스냅샷도 `stale`과 경과 시간을 표시해 먼저 사용하고, 갱신 상태를 최대 3분 추적한다.
- 원 사이트 확인 실패 시 저장 결과가 있으면 그 결과를 유지하고 실패 사실을 표시한다.
- AWS 장애로 D1 백업을 쓰면 정렬·가격 범위는 적용하지만 AWS cursor 기반 추가 페이지는 기대하지 않는다.
- 보기 조건별 cursor는 서로 섞지 않는다. 사이트·정렬·가격 범위가 달라지면 해당 보기의 첫 cursor부터 사용한다.

## 코드와 회귀 계약

- 브라우저 상태와 전환: `web-backend/public/app.js`
- 페이지 도달성 계산: `web-backend/public/pagination.mjs`
- AWS 캐시·큐·검색 응답: `aws-runner/runner.mjs`
- SQLite 스냅샷: `aws-runner/search-index.mjs`
- 원 사이트 단기 캐시: `cloudflare/live-search.mjs`
- D1 장애 대체: `cloudflare/worker.mjs`, `cloudflare/d1-search.mjs`
- 결정론 검증: `harness/ui-pagination-contract.mjs`, `harness/ui-pagination-summary-contract.mjs`, `harness/search-session-policy-contract.mjs`, `aws-runner/search-index-harness.mjs`, `cloudflare/harness.mjs`

운영 브라우저 검증은 `전체 검색 → 1페이지에서 3페이지 → 중고나라 → 전체 → 낮은 가격 → 높은 가격 → 가격 범위 → 다른 사이트` 순서로 반복한다. 각 전체 보기 전환에서 `1 2 3 4`가 다시 열리는지, 상단·하단 방향 버튼이 같은 페이지로 움직이는지, 결과 수·정렬 방향·콘솔 오류를 확인한다.
