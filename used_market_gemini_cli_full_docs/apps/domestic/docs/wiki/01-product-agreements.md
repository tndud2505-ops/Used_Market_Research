# 제품 합의

기준일: 2026-08-24

## 확정된 방향

1. `moajung.com`은 통합검색 흐름과 원본 링크 이동 UX를 참고한다. 화면·로고·문구를 그대로 복제하지 않는다.
2. 우리 서비스는 단순 통합검색보다 컴퓨터 부품 분해·정규화·가격 기준·기회 신호·가격 이력을 추가해 차별화한다.
3. KStock은 정보 밀도, 좌측 내비게이션, 요약 지표, 차트, 엔진 상태 패널의 참고점이다. 브랜드 자산과 고유 화면을 복사하지 않는다.
4. 피드백은 `search_truth`와 `ui_parity`를 분리한다. 검색이 실제로 됐는지와 UI 기준을 만족하는지는 같은 점수로 섞지 않는다.
5. 매물 가격은 참고용이다. 서비스는 거래 당사자가 아니며, 플랫폼·상태·구성 차이를 고지한다.
6. 검색어·카테고리가 같으면 사이트 탭·정렬·가격 범위 변경은 새 검색으로 보지 않는다. 같은 검색 세션의 보기 조건만 바꾸고 페이지는 1페이지로 초기화한다.
7. 전체 검색 뒤 사이트 탭을 누르면 저장 결과를 즉시 보여준 다음 선택 사이트만 비동기 보강한다. 사용자가 결과를 보기 전에 같은 원 사이트를 다시 기다리게 하지 않는다.
8. `낮은 가격`을 누르면 현재 검색 세션의 결과를 숫자 가격 오름차순으로 즉시 재배열한다. 정렬 변경만으로 원 사이트를 다시 수집하지 않는다.
9. 캐시가 있으면 최신성 경계를 넘었더라도 저장 결과를 경과 시간과 함께 먼저 표시하고, 원 사이트 갱신은 백그라운드에서 수행한다. 캐시가 전혀 없는 첫 검색만 동기 수집한다.
10. 사이트 보강으로 90개를 받으면 1~3페이지는 즉시 이동하고 4페이지는 cursor 한 번으로 이동할 수 있게 표시한다. 먼 페이지를 누르게 해 중간 cursor를 연속 요청하지 않는다.

## 검색 전환 계약

| 사용자 행동 | 즉시 응답 | 후속 수집 |
| --- | --- | --- |
| 전체 → 특정 사이트 | 전체 스냅샷에서 해당 사이트만 즉시 표시 | 선택 사이트를 160→320개 후보로 보강하고 3페이지(90개)까지 미리 읽음 |
| 전체 → 낮은 가격 | 현재 결과를 즉시 숫자 가격순으로 재배열한 뒤 같은 SQLite 스냅샷의 정렬 결과로 교체 | 없음 |
| 특정 사이트 → 낮은 가격 | 현재 사이트 결과를 즉시 숫자 가격순으로 재배열한 뒤 같은 SQLite 스냅샷의 정렬 결과로 교체 | 없음 |
| 가격 범위 변경 | 같은 SQLite 스냅샷에 범위를 적용하고 1페이지 이동 | 없음 |
| 이미 받은 페이지 이동 | 같은 스냅샷에서 즉시 30개 표시 | 없음 |
| 바로 다음 페이지 이동 | cursor 한 번으로 다음 30개 조회 | 없음 |
| 결과 창 끝에서 `다음` | 기존 결과를 유지 | 현재 사이트의 최신 후보 범위를 160→320→480→640개로 확장 |

사이트·정렬·가격 범위를 바꿔도 검색어와 카테고리가 같으면 수집 키는 유지한다. 페이지 커서는 사이트 보기·정렬·가격 범위를 포함해 다른 보기 조건에서 재사용하지 않는다.

세부 캐시 층과 페이지 도달성 규칙은 [캐시와 검색 UX](./08-cache-search-ux.md)를 따른다.

## 모아줌과의 비교 기준

모아줌은 여러 플랫폼을 한 번에 검색하고 가격·정렬·원본 링크 이동을 제공한다. 우리 쪽 비교 기준은 다음과 같다.

- 같은 키워드로 각 플랫폼의 raw count를 확인한다.
- 정규화 후 남은 매물 수와 원본 URL을 확인한다.
- 가격이 없는 글·판매완료·업체/광고성 글은 왜 제외됐는지 표시한다.
- 컴퓨터 부품은 GPU·CPU·RAM·SSD·완제품 구성으로 분해해 같은 기준으로 비교한다.
- 가격 그래프는 실제 관측값과 수동 기준값을 시각적으로 분리한다.

## 아직 확정하지 않은 것

- 모아줌처럼 6개 플랫폼 전체를 지원할지 여부. 현재 운영 기본은 중고나라·번개장터·헬로마켓·리씽크몰 네 곳이다.
- Cloudflare Worker에서 Browser Rendering을 직접 사용할지, 공개 Node 러너를 유지할지 여부. 현재 구현은 공개 Node 러너 호출 방식이다.
