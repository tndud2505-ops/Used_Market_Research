# 2026-08-24 캐시·페이지 UX

## 문제

전체 검색 뒤 중고나라 같은 사이트로 전환하면 90개를 선읽었는데도 1페이지에서 2페이지만 보여 사용자가 `1→2→3→4` 순서로 눌러야 했다. 과거의 먼 페이지 연속 cursor 방지 수정이 실제 도달 가능한 3·4페이지까지 숨긴 것이 원인이었다.

## 변경

- 페이지 렌더러에 현재 `maxNavigablePage`를 전달한다.
- 도달 경계가 7페이지 이하면 1페이지부터 경계까지 모두 표시한다.
- 90개 선읽기 뒤 `1 2 3 4 … 마지막`을 표시한다.
- 이미 받은 1~3페이지는 즉시 이동하고 4페이지는 cursor 한 번만 요청한다.
- 도달 경계가 길어지면 처음·현재 주변·도달 경계·마지막만 표시한다.
- 앱 모듈 버전을 `search-session-v7`, 페이지 모듈 버전을 `pagination-v7`로 올려 기존 브라우저 캐시가 이전 코드를 계속 쓰지 않게 한다.

## 정책 기록

브라우저, AWS 메모리, SQLite, 원 사이트 단기 캐시, D1 백업과 사이트·정렬·가격·페이지별 수집 경계를 `docs/wiki/08-cache-search-ux.md`에 통합했다.

## 검증

- `harness/ui-pagination-contract.mjs` 58개 계약 통과: 90개 선읽기, 1→4 직접 도달, 긴 도달 범위 축약, 클릭당 cursor 요청 1회.
- `harness/search-session-policy-contract.mjs` 45개 계약 통과: 정렬·가격의 재수집 금지와 페이지 cursor 1회 경계.
- `npm test` 전체 통과.
- `npm run index:harness` 220개 계약 통과.
- `npm run cloudflare:harness` 45개 계약 통과.
- 실제 운영 브라우저 반복 흐름과 Cloudflare 배포 결과는 배포 완료 후 이 문서에 기록한다.
